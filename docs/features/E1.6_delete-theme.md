# E1.6 — Delete a theme / restore defaults

- **Epic:** E1 · User-Defined Themes
- **Stage:** testing  *(implemented on `dev`; verified live 2026-07-01)*
- **Platform:** web (then iOS)
- **Depends on:** E1.1 (data-driven themes), E1.4 (create)

## 1. Summary
Let the user **delete a single theme** and **restore the default 5**. Deleting a theme removes it from
the live list; any of its **held** names become **exiting positions** (no longer in any theme → sold to
$0 on the next rebalance/realign, exactly like a swapped-out name). A **clear warning** is shown at delete
time *and* surfaced in the rebalance preview before any liquidation.

> **On "clear all themes":** the allocator needs ≥ 1 theme (an empty `state.themes` falls back to the
> default 5 by design), so a true zero-theme state isn't meaningful. "Clear all / start over" is therefore
> served by **Restore the default 5** (a factory reset of the theme structure). Deleting your *last*
> remaining theme is blocked — use Restore defaults instead.

## 2. Design
- **`deleteTheme(key)`:** confirm (warn if it has held names — they'll be sold on the next rebalance);
  materialize `state.themes`, drop the theme; delete its `state.themeTickers[key]` entry; `rebuildThemeOf`;
  `savePortfolio`; `renderAll`. Blocked if it's the only theme left. No immediate rebalance — the sell
  happens on the next Calculator rebalance/realign (its names are now `_exit`).
- **`restoreDefaultThemes()`:** confirm; `state.themes = null` + `state.themeTickers = null` → back to the
  factory 5 themes × default names; `savePortfolio`; `renderAll`. (Custom themes and swaps are cleared;
  holdings aren't sold *now* but off-default names become exiting positions on the next rebalance.)
- **Rebalance-preview warning:** in `renderRebalanceOutput`, if any **held** names are being sold to $0
  because they're no longer in a theme (theme deleted, ticker removed, or swapped out), show a warning
  banner listing them — the "before any liquidation" heads-up.
- **UI:** a **✕** button per theme in the Fundamentals allocation legend (next to ✎ / ＋ name); a
  **"↺ Restore default 5"** button near "➕ New theme".

## 3. Acceptance criteria
- [ ] Delete a theme with no holdings → it disappears everywhere; allocations renormalize across the rest.
- [ ] Delete a theme **with** holdings → confirm warns which names will be sold; after delete those names
  are exiting positions (target $0); the next rebalance preview shows the sells + a warning banner.
- [ ] Deleting the **last** theme is blocked with a helpful toast.
- [ ] **Restore defaults** → back to the original 5 themes/names; custom themes gone; persists on reload.
- [ ] Regression: with the default 5 and no deletions, nothing changes.

## 4. Implementation notes
- `www/index.html`: `deleteTheme`, `restoreDefaultThemes`; `✕` (`data-delth`) in the legend + a Restore
  button + delegated handlers; exiting-positions warning banner in `renderRebalanceOutput`. No server/data change.
