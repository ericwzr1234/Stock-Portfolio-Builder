# E1.5 — Rename / recolour a theme

- **Epic:** E1 · User-Defined Themes
- **Stage:** testing  *(implemented on `dev`; verified live 2026-07-01)*
- **Platform:** web (then iOS)
- **Depends on:** E1.1 (data-driven theme list), E1.4 (create — same modal/palette patterns)

## 1. Summary
Let the user edit an existing theme's **display name** and **colour**. Because E1.1 routes every read
through `themes()` / `themeByKey()`, a name/colour change propagates **consistently everywhere** — Prices
cards, the allocation bar + legend, the Screener theme chips, holdings grouping, and the History labels —
with no other work. **The theme's `key` never changes**, so membership (`themeTickers`), holdings mapping,
the curated universe, and version snapshots all stay intact.

## 2. Design
- **`renameTheme(key, name, color)`:** materialize `state.themes` (defaults → concrete if still null),
  find the theme by `key`, set `name` (+ `color`), **keep the `key`**; `rebuildThemeOf()` (theme objects
  changed), `savePortfolio()`, `renderAll()`. A settings change (like weights/cap) — saved immediately, no
  rebalance, no version checkpoint (names carry no allocation effect).
- **UI:** a small **✎** button next to each theme in the Fundamentals allocation legend → an **Edit theme**
  modal: a name field (pre-filled) + the same colour-swatch picker as *New theme* (current colour
  pre-selected). Save applies it everywhere.
- **Edge cases:** empty name → rejected (toast). Duplicate name → allowed (keys stay unique; names may
  repeat). Colour outside the palette → the theme keeps its current colour unless a swatch is picked.

## 3. Acceptance criteria
- [ ] Rename a theme → the new name shows in Prices, the allocation legend/bar, Screener chips, holdings,
  and History; the **key is unchanged** (membership, universe match, and past snapshots still work).
- [ ] Recolour a theme → the new colour shows in the swatch/legend/bar/chip everywhere.
- [ ] Renaming a **default** theme (e.g. Stablecoin) doesn't break its curated Screener list (keyed by
  `key`, not name) or its default tickers.
- [ ] Empty name rejected; persists across reload; no unintended rebalance (allocations unchanged by a
  pure rename).

## 4. Implementation notes
- `www/index.html`: `renameTheme` + `openEditTheme`; a `✎` button (`data-editth`) per legend item +
  delegated handler; reuse `THEME_PALETTE` + the `.ct-sw` picker from `openCreateTheme`. No server/data change.

## 5. Test plan / results  *(verified live 2026-07-01, read-only)*
- ✅ Renamed default `stablecoin` → "Payments & Crypto" + recoloured: `themeByKey` returns the new
  name/colour (propagates everywhere), and the **key stayed `stablecoin`**.
- ✅ **Key-stability:** `isCuratedTheme('stablecoin')` still true (curated Screener list resolves) and
  `tickersOf('stablecoin')` intact (membership unaffected).
- ✅ **No allocation change** from a pure rename (maxDiff = 0).
- ✅ Edit modal pre-fills the current name and pre-selects the current colour swatch.
- ⏳ Pending user click-through.

## 6. iOS migration notes
- Pure `www/index.html` change → `npx cap sync ios`; the edit modal inherits the `.native` skin. `state.themes`
  already persists (localStorage / LAN sync). No native change.
