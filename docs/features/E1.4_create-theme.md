# E1.4 — Create a new theme

- **Epic:** E1 · User-Defined Themes
- **Stage:** testing  *(implemented on `dev`; verified live 2026-06-26 — see §5. Awaiting user click-through before merge.)*
- **Platform:** web (then migrate to iOS)
- **Depends on:** E1.1 (data-driven theme list). Pairs with E1.2 (fill it) and E1.3 (search off-universe names).

## 1. Summary
Let the user **create a brand-new theme** — a name + colour (e.g. "Semiconductors") — that appears across
every tab and starts empty, ready to fill with E1.2 (Add) / E1.3 (Search). This is the headline of the
epic. It has one non-obvious requirement surfaced by testing: **an empty theme must take 0% of the
allocation until it has names**, otherwise it siphons undeployable weight (see §2b).

## 2. Design

### 2a. State & creation
- `createTheme(name, color)`:
  - **Materialize** the live list: `state.themes = themes().map(t=>({key:t.key,name:t.name,color:t.color}))`
    (turns the `null`→defaults case into a concrete array on first creation), then push
    `{key, name, color}`.
  - **Key** = a slug of the name (`semiconductors` → `semiconductors`; lowercased, non-alphanumerics
    stripped); if it collides with an existing key, append `-2`, `-3`, … New themes have **no**
    `DEFAULT_THEME_TICKERS` entry, so `tickersOf(key)` → `[]` (the E1.1 coalesce) — i.e. empty.
  - **Colour** = the chosen colour; default to the next unused colour from a small palette.
  - `rebuildThemeOf()`, then **`savePortfolio()`** (persists `state.themes`) and re-render. This is a
    *settings* change saved immediately — the same pattern as editing weights / penalties / the cap
    (no version checkpoint; an empty theme changes no holdings). Filling it later via E1.2 **is** a
    checkpoint.

### 2b. Model rule — empty themes get 0% *(the important part; verified)*
Today `computeAllocation` would median-fill a names-less theme's missing factors and hand it a real
slice. Measured live: a 6th empty theme drew **14.1%**, and the book deployed only **85.9%** (that 14%
has no names to buy). Fix:
- In `computeAllocation`, treat a theme with `tickersOf(key).length === 0` as **excluded**: it gets
  `alloc = 0` and is left out of the median computation, score normalization, and `applyThemeCap`.
- Scoring/normalization/cap run over the **funded** themes only, so they still **sum to 100%** and the
  book fully deploys.
- The cap's `N` and the equal-weight base derive from the **funded** theme count (an empty theme isn't a
  real slice yet).
- Empty themes are still **returned** in the rows (at 0%) so they render everywhere (Prices card,
  legend, holdings group) with a "no names yet — add some" affordance.
- **Regression:** with the default 5 (all funded) this is a no-op — identical to today.

### 2c. UI
- A **"➕ New theme"** button in the **Fundamentals & Allocation** tab (the model-settings home, next to
  the allocation legend / cap / weights — and the natural future home for E1.5 rename & E1.6 delete).
- Opens a small modal: **Name** (text) + **Colour** (a swatch picker from the palette, or a colour
  input). "Create" validates and calls `createTheme`.
- After creation the new theme shows everywhere at **0%** with a hint to add names (tap a Screener stock
  → "Add", or search in E1.3).

### 2d. Edge cases
- **Empty / whitespace name** → reject with a toast.
- **Duplicate name/key** → key is uniquified (`-2`); the display name may repeat but the key won't.
- **Sensible max** (e.g. 12 themes) → beyond it, toast and block (keeps the allocation readable; the cap
  `1.5/N` stays above the `1/N` floor well past this).
- **Colour reuse** → allowed (purely visual); optionally hint if it duplicates another theme's colour.
- **First creation** flips `state.themes` from `null` to a concrete array that includes the 5 defaults —
  verify the app still behaves identically for those 5 (it must, since the content is the same).

### 2e. Scope boundaries
- **Filling** a theme is E1.2 (Add from Screener) / E1.3 (Search any ticker). E1.4 only creates it.
- **Rename / recolour** an existing theme is **E1.5**; **delete / delete-all / restore-defaults** is **E1.6**.

## 3. Acceptance criteria
- [ ] Create "Semiconductors" → it appears in Prices, Fundamentals/allocation legend, holdings grouping,
  and the Screener falls back gracefully (no curated list yet) — with **0%** allocation and a "add names"
  hint.
- [ ] **Empty theme = 0%, book deploys 100%.** With ≥1 empty theme, funded themes' allocations sum to
  100% and `planTrades` targets sum to the full book (no siphon).
- [ ] Fill it via E1.2 Add → it takes a real, model-driven weight and the whole book re-ranks (per E1.2).
- [ ] **Persists** across reload (saved to `portfolio.json`); a later rebalance snapshots it into history.
- [ ] **Regression:** with the default 5 funded themes, allocations/targets are byte-for-behaviour
  identical to today (the empty-theme rule and `state.themes` materialization are no-ops there).
- [ ] Key uniqueness holds; empty name rejected; the theme count cap is enforced with a clear message.

## 4. Implementation notes  *(filled during implementation)*
- `www/index.html`: `createTheme(name,color)` + slug/uniquify helper; the empty-theme exclusion in
  `computeAllocation` (partition funded vs empty; score/normalize/cap on funded; empties → 0); the
  "➕ New theme" button + modal in the Fundamentals tab + handlers; a small colour palette. Empty-state
  hints in `renderPrices` / holdings / `renderScreener`. No `server.py` / data-file change.

## 5. Test plan / results  *(verified live 2026-06-26, real book in the browser, read-only — nothing saved)*
- ✅ **Empty theme = 0%, book deploys 100%.** A new empty "Semiconductors" theme drew **0%** (flagged
  `empty`), the 5 funded themes summed to 100%, and `planTrades` deployed the full book — the ~14% siphon
  is gone.
- ✅ **Inert to existing themes.** With the empty theme present, the 5 funded allocations were
  **byte-identical** (maxDiff = 0) to the default — adding a theme changes nothing until it has names.
- ✅ **Filling works.** Putting one name in the new theme gave it a real, model-driven weight (~30%) and
  re-ranked the whole book (per E1.2).
- ✅ **Default 5 unchanged** (5 funded, sum 1, 100% deployed).
- ✅ **Helpers / UI.** `slugifyThemeKey` makes unique keys ("Semiconductors"→`semiconductors`,
  "Data Providers"→`dataproviders`, no clash with the existing `data`); the New-theme modal renders
  (name field, 12 colour swatches, Create button).
- ⏳ Pending **user click-through** (create a theme, see it at 0%, fill it from the Screener, Apply) before
  merge to `main`.

## 6. iOS migration notes
- Pure `www/index.html` change → Mac runs `npx cap sync ios`. **No native/Swift change.** The new button
  + modal inherit the `.native` skin (give the colour picker and Create button adequate touch targets in
  the `.native { … }` block). `state.themes` already persists through the same localStorage / LAN-sync
  path (E1.1), so a created theme syncs with no extra work.
