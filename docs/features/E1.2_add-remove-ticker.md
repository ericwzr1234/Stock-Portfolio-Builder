# E1.2 — Add / remove a single ticker in a theme

- **Epic:** E1 · User-Defined Themes
- **Stage:** done  *(integrated to `main` 2026-06-26; verified live — see §5)*
- **Platform:** web (then migrate to iOS)
- **Depends on:** E1.1 (data-driven themes — membership already dynamic & version-snapshotted)

## 1. Summary
Today the only way to change a theme's names is **Swap** — tap a Screener stock, pick a same-theme
holding to *replace*, and the theme stays the same size. E1.2 generalizes that into two independent
primitives: **Add** a ticker to a theme (it grows) and **Remove** a ticker from a theme (it shrinks).
Theme size is already variable — within-theme weight is `perTheme = tickersOf(key).length`, and the
cap/equal-weight derive from it (E1.1) — so the engine needs no change. We reuse the existing
**preview → "Apply & save" → version snapshot** rail, so every add/remove is one undoable checkpoint
exactly like a swap. This is the second foundation card: with it you can compose a theme's names;
searching for off-universe tickers is **E1.3**, creating brand-new themes is **E1.4**.

## 2. Design

### 2a. Data model — *no new state*
Uses the existing `state.themeTickers` ({themeKey:[syms]}), already persisted (save/load) and captured
in every version snapshot (E1.1 also snapshots `state.themes`). Add/remove are just array edits to a
theme's membership, written through the same "promote the full map from defaults, then edit one theme"
pattern `doSwap` already uses (line ~1360).

### 2b. Shared primitive (refactor `doSwap`)
Extract the common tail of `doSwap` into one helper so swap, add, and remove share it:
```
async function setMembership(themeKey, newArr, fetchSyms){
  const map={}; themes().forEach(t=>{ map[t.key]=tickersOf(t.key).slice(); });   // seed live map
  // enforce one-theme-per-ticker: remove any newly-present sym from other themes
  newArr.forEach(s=>{ Object.keys(map).forEach(k=>{ if(k!==themeKey) map[k]=map[k].filter(x=>x!==s); }); });
  map[themeKey]=[...new Set(newArr)];
  state.themeTickers=map; rebuildThemeOf();
  if(fetchSyms&&fetchSyms.length){ /* dsQuotes + dsFundamentals for new syms (as doSwap does) */ }
  if(isInit()){ switchView("calc"); renderCalc(); const plan=planTrades(0,"full"); lastPlan=plan;
    if($("#addCash"))$("#addCash").value="0"; renderRebalanceOutput(plan); }
  else { renderAll(); toast("Theme updated — will apply on your next Build"); }
}
```
- **`addTicker(themeKey, sym)`** → `setMembership(themeKey, [...tickersOf(themeKey), sym], [sym])`.
- **`removeTicker(themeKey, sym)`** → `setMembership(themeKey, tickersOf(themeKey).filter(x=>x!==sym), [])`.
- `doSwap` becomes: `setMembership(themeKey, <current with oldSym replaced by newSym>, [newSym])` — behaviour
  unchanged (this is a regression check).

### 2c. Commit path — *unchanged*
The preview's existing **"✓ Apply & save this rebalance"** button → `applyRebalance(plan)` (line 1239)
already: applies trades, **drops fully-liquidated non-member names** (line 1250 — handles a removed
held name), `pushVersion(buildTxn("REBALANCE", …))` (snapshots holdings + settings + `themeTickers` +
`themes`), `savePortfolio()`, `renderAll()`. So **no commit/persistence/versioning work** — add/remove
are recorded and undoable for free.

### 2d. UI (minimal)
- **Add (from the Screener).** Tapping a stock currently opens the swap modal (`openSwap`, line 1341).
  Add a button at the top of that modal: **“➕ Add as a new name (don’t replace anything)”** → calls
  `addTicker(themeKey, newSym)` and closes the modal. The existing “replace a holding” radios stay
  below for the swap path. (One modal, two clearly-labelled actions — discoverable, minimal new UI.)
- **Remove.** In the Calculator's **holdings table** (`holdingsTable`, line 1133), add a small
  `✕` control on each themed stock row → confirm → `removeTicker(themeKey, sym)`. (Same affordance can
  later appear on the Prices theme cards; holdings table is enough for E1.2.)
- Both routes land on the standard rebalance **preview**, which the user reviews and applies — identical
  to the swap UX they already know.

### 2e. Algorithm / behaviour notes
- **One theme per ticker** (preserves the `themeOf` 1:1 map): adding a sym that already lives in another
  theme **moves** it (removed from the old, added to the new) and we toast “moved from <old theme>”.
- **Removing a held name** → it's no longer in `membership()`, so `planTrades` targets it $0 → the
  preview shows the sell → on Apply, `applyRebalance` liquidates and drops it (existing line 1250).
- **Within-theme weights re-spread automatically** (5→6 names = 16.7% each; 5→4 = 25% each) and the
  cap/cross-theme weights recompute via the E1.1 engine. No special-casing.

### 2f. Edge cases
- Add a sym already in **this** theme → toast “already in <theme>”, no-op (mirror `openSwap` guard line 1334).
- Add a sym held/membered in **another** theme → move semantics (2e), toast the move.
- Remove the **last** name in a theme → allowed, but warn “<theme> will have no names (≈0% weight)”.
  Deleting the theme entirely is **E1.6**, not here.
- **Pre-build** (no holdings yet) → membership updates and is kept; no rebalance preview (nothing to
  rebalance) — it takes effect on the next **Build initial**.
- Add a ticker with no live quote/fundamentals yet → `setMembership` fetches it first (as `doSwap` does);
  if the fetch fails it still adds (model median-fills the missing factors, same as any thin name).

### 2g. Scope boundaries
- Adding a ticker **outside the curated Screener universe** (free-text search + validate) is **E1.3**.
  E1.2's Add entry point is the Screener (universe stocks) only.
- Creating/renaming/deleting **themes** is E1.4–E1.6.

## 3. Acceptance criteria
- [ ] **Add** a Screener stock as a new name → its theme grows by one, within-theme weights become
  `1/(n+1)`, the preview funds the buy by trimming the rest, **Apply** records a REBALANCE version, and
  **undo** restores the prior membership + holdings.
- [ ] **Remove** a themed name → theme shrinks, the name is sold to $0 in the preview, on Apply it's
  dropped from holdings, a version is recorded, and **undo** restores it.
- [ ] **One-theme-per-ticker** invariant holds (a sym never appears under two themes after an add/move).
- [ ] **Swap regression:** the existing tap-to-replace swap still produces the identical result it does
  today (it now routes through `setMembership`).
- [ ] Cap & weights adapt correctly to the new theme size (per E1.1); allocations still sum to 100%.
- [ ] Persists & version-snapshots (add/remove survive reload and undo/redo/revert).
