# E1.3 — Ticker search & validate (add any name to a theme)

- **Epic:** E1 · User-Defined Themes
- **Stage:** testing  *(implemented on `dev`; verified live 2026-06-26 — see §5. Awaiting user click-through before merge.)*
- **Platform:** web (then iOS) — **note: this card adds a server route + iOS data-layer call** (see §2c)
- **Depends on:** E1.2 (add primitive), E1.4 (themes to add into)

## 1. Summary
Let the user **search for any ticker or company — including names not in the curated Screener universe**
(e.g. AMD, TSM, AVGO) — validate it live on Yahoo, preview it, and **add it directly to a theme**. Per
the user's requirement, the primary entry point is **inline in the Fundamentals & Allocation tab** (pick
a theme → search → add, no detour), with the **Screener** offering the same search as a secondary route.
This is the piece that lets a custom theme (E1.4) hold names the screener doesn't already list.

## 2. Design

### 2a. Flow
1. User opens **Search** (from a theme in the Fundamentals tab, or from the Screener) → a search modal.
2. Types a symbol or company name → debounced lookup → a short results list (symbol · name · exchange).
3. Picks a result → **Add to «theme»** → routes through **`addTicker(themeKey, symbol)`** (E1.2):
   move-semantics, fetch the name's quote + fundamentals, then the standard **rebalance preview →
   "Apply & save"** (one undoable checkpoint). Off-universe names work because membership is dynamic
   (E1.1) and tickers no longer need to be in `universe.json`.

### 2b. Entry points
- **Fundamentals & Allocation tab (primary).** The theme-management home (already has "➕ New theme").
  Each theme in the allocation legend gets a small **"＋ add name"** control → opens the search modal
  **scoped to that theme**. So: create a theme here, then fill it here — all in one tab.
- **Screener tab (secondary).** A **"🔍 Search any ticker"** box above the curated lists → same modal,
  but with a **theme picker** (since no theme is pre-selected). Keeps the existing tap-to-add/swap flow.
- Both reuse one `openTickerSearch(themeKey?)` modal.

### 2c. Data layer — new search call (the one new bit of plumbing)
- Add **`dsSearch(query)`** to the platform-agnostic layer → returns `[{symbol, name, exchange, type}]`.
  - **Web:** new **`/api/search?q=`** route in `server.py` proxying Yahoo's free search endpoint
    (`https://query2.finance.yahoo.com/v1/finance/search?q=…`), returning the `quotes` array trimmed to
    equities. (Mirrors the existing quote/fundamental proxies; same cookie/crumb handling not needed for
    search.)
  - **iOS:** `dsSearch` hits the same Yahoo endpoint directly via **CapacitorHttp** (no server), mirroring
    how `dsQuotes`/`dsFundamentals` already branch on `NATIVE`.
- **Validation on add:** the chosen symbol's quote + fundamentals are fetched (via `setMembership`'s
  existing fetch). If no price comes back, warn ("couldn't load data for X") but still allow the add (the
  model median-fills, same as any thin name) — or block; decide at sign-off (default: **warn + allow**).

### 2d. UI (minimal, reuses existing patterns)
- Search modal: a text input (debounced ~250 ms) + a results list of up to ~8 matches; each row is a
  button "Add to «theme»". Loading + empty ("no matches") states. Filter out indices/currencies; keep
  equities (and optionally ETFs).
- Fundamentals legend item → a `＋` button (`data-addto="<themeKey>"`); Screener → a search bar that opens
  the modal with a theme `<select>`.

### 2e. Edge cases
- **No / ambiguous results** → show "no matches", let the user refine.
- **Symbol already in a theme** → `addTicker` handles it (toast "already in X" or **move** if it's in
  another theme — E1.2 semantics).
- **Off-universe thin data** (no fundamentals) → median-filled by the model; flagged in the preview.
- **Non-equity result** (ETF/index/FX) → filtered out, or labelled; default: hide non-equities.
- **Offline / search fails** → toast; fall back to "enter an exact symbol" (validate via a direct quote
  fetch) so the feature degrades gracefully without the search endpoint.

### 2f. Scope boundaries
- Recommending names (from picks → E1.7; from the theme **name** → E1.8) is separate. E1.3 is
  user-initiated search + add.
- Creating/renaming/deleting themes is E1.4 / E1.5 / E1.6.

## 3. Acceptance criteria
- [ ] From the **Fundamentals tab**, pick a theme → search "AMD" (not in the universe) → add it → it joins
  that theme, the book re-ranks, **Apply** records an undoable version. No trip to the Screener needed.
- [ ] The **Screener** search adds the same way, with a theme picker.
- [ ] Search returns sensible matches for both a **symbol** ("TSM") and a **company name**
  ("Taiwan Semiconductor"); non-equities are filtered.
- [ ] An off-universe name with thin data still adds and is median-filled (preview flags it); a bad/empty
  query shows "no matches".
- [ ] **Web + iOS parity:** web via `/api/search`, iOS via CapacitorHttp — same `dsSearch` contract.
- [ ] Adds persist + version-snapshot (via E1.2's rail) and survive reload / undo.

## 4. Implementation notes  *(filled during implementation)*
- `server.py`: add `/api/search` (Yahoo `v1/finance/search` proxy; trim to equities). 
- `www/index.html`: `dsSearch(query)` (NATIVE branch); `openTickerSearch(themeKey?)` modal + debounce +
  results render; `＋ add name` controls in the Fundamentals legend; a search bar in the Screener; wire
  results → `addTicker`. Reuse `setMembership` for fetch+preview. No data-file change.
- iOS data layer: `dsSearch` via CapacitorHttp to the Yahoo endpoint.

## 8. Refinement 1 (2026-06-26) — cached directory + "Other" list
**Why.** (a) The live-search dependency was fragile: a long-running app server still on pre-E1.3 code
404s `/api/search` → "no matches" (Python doesn't hot-reload — **restart the server** to pick up
`server.py` changes). (b) The user wanted to add a found name without committing it to a theme yet.

**Search source (`server.py`).** First tried a cached directory from **NASDAQ Trader's symbol files** —
but those now sit behind an **Incapsula bot wall** (a 212-byte challenge page; even `curl` is blocked),
and the partial NASDAQ-only file it had grabbed once **omitted every NYSE name (the "TSM returns TSMG/TSMU
but not TSM" bug)**. Resolution:
- **Default = Yahoo's live search** (`/api/search` → `search_yahoo`) — reliable, no setup, covers
  NASDAQ + NYSE + ADRs. Verified: `TSM`→Taiwan Semiconductor (NYSE) first, `TSLA`→Tesla, name search
  "berkshire"→BRK-B.
- **Optional instant local cache** = the **SEC's official `company_tickers.json`** (10,433 names incl.
  TSM/ADRs). SEC's fair-access rule **requires a contact email in the User-Agent** (a UA without one gets
  **403**), so the cache is **opt-in via env `PB_SEC_CONTACT=you@email`** — keeping a personal email out
  of committed/shareable code. When set, the directory is cached to `ticker_directory.json` (git-ignored),
  refreshed >24h, warmed on startup; `search_directory` uses it and falls back to Yahoo live if it's empty.
- Ranking (cache mode): exact symbol → prefix → symbol-contains → name-contains. **On add**, the name's
  live quote+fundamentals are fetched and it's scored like any other (thin data → existing penalty/compute).

**"Other" (unassigned) list.** `state.otherList` (persisted + version-snapshotted, mirroring
`themeTickers`/`themes`) holds searched names not yet assigned — **excluded from the allocation** (not in
`membership()`, no target; verified). The search modal always shows a theme picker **+ an "Other (decide
later)" option** (pre-selecting the theme it was opened from). An **"Other — unassigned" panel** in the
Fundamentals tab lists parked names, each with a **"Move to…" theme selector** (→ `addTicker`, which
previews the realign) and a remove ✕.

**Verified live (read-only):** search returns `TSM`→Taiwan Semiconductor first (the reported bug — fixed),
plus AMD, TSLA, and name searches (berkshire→BRK-B); a parked name is excluded from membership +
allocation and rides into version snapshots; the picker offers Other + pre-selects the opened theme; the
Other panel renders move/remove controls. The opt-in SEC cache was verified at 10,433 names incl. TSM.

**iOS.** The directory cache is a server/web feature; on iOS `dsSearch` keeps Yahoo live search (or the
LAN-synced server's `/api/search`). The watchlist flows through the same localStorage/LAN persistence — no
native change.

## 9. Refinement 2 (2026-06-26) — search → Screener watchlist, not the portfolio
**Why.** Selecting a searched name shouldn't touch the book or rebalance immediately — it should land in a
**watchlist** the user reviews, then deliberately add to a theme.

- The Refinement-1 "Other (unassigned)" list is replaced by a **Watchlist** (`state.watchlist` =
  `[{sym,theme}]`, persisted + version-snapshotted; migrates old `otherList`). It lives **at the top of
  the Screener tab**, not Fundamentals.
- **Search adds to the watchlist only** — no theme picker in the search modal, **no rebalance**. The
  fetched name is parked (with its live price/day-move) and is **excluded from the allocation** (not in
  `membership()`).
- Searching from a theme's **"＋ name"** (Fundamentals) tags the watchlist item with that theme as a
  **hint**, pre-selected in its "Add to theme…" dropdown; searching from the Screener has no hint.
- **Committing** is a deliberate step in the watchlist: pick a theme → `addTicker` → the usual rebalance
  **preview** in the Calculator → **Apply** (persists the watchlist removal + the new membership).
- A remove ✕ drops a name from the watchlist without touching the book.

**Verified live (read-only):** a watchlisted name is excluded from membership + allocation and rides into
version snapshots; the Screener renders the watchlist with the theme hint pre-selected; the search modal
has no theme picker (search → watchlist only).
