# E3.4 — Integration + source labeling + toggle

- **Epic:** E3 · **Stage:** done *(integrated to `main` 2026-07-13)*
- **Platform:** web + iOS · **Depends on:** E3.2

## Summary
Make the model consume computed metrics as the **primary** source, with a user **toggle** (default on) that reverts
to Yahoo's pulled fields, per-metric **source labeling**, and a **computed-vs-pulled compare** surface.

## What shipped (`www/index.html`)
- **Toggle:** `state.computeFromStatements` (default `true`). A **`Compute metrics from statements`** checkbox in the
  Fundamentals config panel; on change → `rebuildFundamentals()` + `renderAll()` + save. A coverage note
  (`→ N/N names computed from statements`). Persisted **top-level** in `save`/`loadPortfolio` like `cap` — and
  **deliberately NOT versioned** (`restoreVersion` untouched): undo/redo must not silently flip the data source.
- **Source provenance:** `state.metricSource[sym][field]` = `computed` | `pulled`, set by `applyComputedMetrics`.
  The detail page tags every metric; the compare surface reads it.
- **Compare surface:** `openSourceCompare()` — a modal listing each holding × each computed metric: the computed
  value and its **% delta** from Yahoo's pulled figure (from the untouched `state.pulled`), flagging >10% gaps
  (ROE/ROA/quick differ by design).
- **Fallback strategy (layered, never hard-fails):** master toggle off → pure pulled app; a symbol with no/partial
  statements → computable fields computed, the rest kept pulled; a field with a missing operand → stays pulled.

## Acceptance criteria
- [x] Toggle off → the app matches the shipped E2 pulled model (all `pulled`, no statement traffic); on → computed.
- [x] Toggle persists across reload; undo/redo does **not** change it.
- [x] Compare surface shows computed vs pulled % deltas; ROE/ROA/quick flagged as expected.
