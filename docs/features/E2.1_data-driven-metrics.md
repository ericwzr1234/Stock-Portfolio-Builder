# E2.1 — Data-driven metric list (foundation)

- **Epic:** E2 · User-Defined Metrics
- **Stage:** design  *(awaiting sign-off — hardened by a 5-agent code audit of `www/index.html`)*
- **Platform:** web (then iOS)
- **Depends on:** the C1 model; mirrors **E1.1** (which made the *theme* list data-driven).
- **Audit:** workflow `e2.1-metric-audit` verified every line below against the code (computeAllocation
  550-604 as of writing).

## 1. Summary
Today the **six scoring metrics** (PEG, EV/EBITDA, Debt/FCF, P/E, avg market cap, momentum) are hardcoded
throughout `computeAllocation`. E2.1 makes the **metric *list*** data (`state.metrics`) — read through a
`metrics()` accessor, exactly like `themes()` — so later cards can let users add/remove metrics and set
weights. It is **invisible and regression-safe**: with the default 6 the app is **byte-for-behaviour
identical** to today. This is the plumbing E2.2 (picker UI), E2.3, E2.4 build on.

**Scope of E2.1 = the ENGINE only.** The weight/penalty *inputs*, the methodology notes, and the
per-theme fundamentals table stay hardcoded to the 6 in this step; generating *those* from `metrics()`
is **E2.2**. Keeping E2.1 engine-only is what makes it provably identical at the default 6.

## 2. Design

### 2a. Data model (mirrors `themes()`/`THEMES`)
- Add a **code-side** `const DEFAULT_METRICS` — an ordered array of 6 **descriptors** (order:
  `peg, ev, dfcf, pe, mcap, mom`). Descriptors hold **closures/functions**, so they live in code and are
  **never serialized**. Each descriptor carries:
  - `key` (`peg|ev|dfcf|pe|mcap|mom`) — also the `state.weights` / `state.penalty` lookup key and the
    `row.<key>` field prefix; `weightInputId` (`#wPeg`…), `defaultWeight` (.20/.20/.20/.15/.10/.15).
  - `getter` — the **existing** closure `effPeg/effEv/effDfcf/effPe/effMcap/momOf` (so mom's
    non-overridability and mcap's 3-tier source are preserved by *pointing at the real fn*, not synthesizing).
  - `valueKind` (`themeMetric` ×4, `avgMcap` for mcap, `momentum` for mom) — dispatches the aggregation.
  - For `themeMetric` kind: `penaltyKey` (`peg|ev|dfcf|pe`), `allowZero` (true only dfcf), `nullExcludes`
    (true only ev/dfcf); `carryKey` (`ev|dfcf` only → wrap getter with the `carry[s][carryKey]` fallback).
    **Absent** for mcap/mom (so they never read `state.penalty` / never inject a default).
  - `readValue(row)` → `obj.value` for themeMetric/momentum, **bare number** for avgMcap (matches
    `r.peg={value…}`, `r.mcap=number`, `r.mom={value…}`); `useMedian` (true for the 5 ratio/mcap, **false**
    for mom); `score(x)` closure carrying direction+guard **verbatim**:
    - peg/ev/pe → `(isNum(x)&&x>0)?1/x:0`
    - dfcf → `(isNum(x)&&x>=0)?1/Math.max(x,0.1):0`  *(0 = debt-free = best, capped at 10)*
    - mcap → `(isNum(x)&&x>0)?Math.max(0,Math.log(x/1e9)):0`  *(log $B, floored at 0)*
    - mom → `isNum(x)?Math.max(0,x):0`  *(raw momentum, downtrends floored at 0)*
  - display metadata `label/sublabel/header/formatter` (for E2.2's UI later).
- Add **`metrics()`** → `state.metrics` (non-empty array) else `DEFAULT_METRICS`; **`metricByKey(k)`**.
- Add **`state.metrics: null`** (null ⇒ defaults).
- **`state.weights` and `state.penalty` stay EXACTLY as they are** — the source of truth for the *numbers*.
  `state.metrics` only governs **which keys exist and in what order**. So every existing weight/penalty
  save/load/undo/migration path is **untouched**.

### 2b. Engine refactor (`computeAllocation` → a loop, byte-identical at default 6)
Each per-metric stage becomes a `metrics().forEach/map` dispatched by descriptor; `wsum`/renorm/cap/return
stay literal. **Iteration order is fixed** (`peg,ev,dfcf,pe,mcap,mom`), so the floating-point sums are
identical operation-for-operation. Steps (audit checklist):
- **Weights:** `wsum = metrics().reduce((a,m)=>a+(state.weights[m.weightKey]||0),0)||1`; `wN[m.key] = …/wsum`.
- **Carry wrap:** for a descriptor with `carryKey`, wrap `m.getter` with the `evGet/dfGet` fallback logic.
- **Row build:** `metrics().forEach(m => row[m.key] = valueKind dispatch)` → `themeMetric(tk, wrapped, state.penalty[m.penaltyKey], m.allowZero, m.nullExcludes)` | `themeAvgMcap(tk)` | `themeMomentum(tk)`.
- **Medians:** only for `useMedian` metrics. **Used/Score:** `r[key+'Used']` (skip for mom), `r[key+'Score']=m.score(used)`.
- **Sums / normalize / blend:** all keyed by `m.key`; `r.alloc = Σ wN[m.key]*r[m.key+'N']`.
- **Empty-theme zero, funded filter, renorm-to-1, cap** (E1.1/E1.4): UNCHANGED, outside the metric loop.
- **Return:** still emit the flat aliases `wPeg/wEv/wDf/wPe/wMc/wMo` (from `wN`, `||0`) **plus** a new
  `wByKey:wN` — so **every downstream reader (fundamentals table, notes, renderCalc, buildTxn) keeps
  working with zero edits** this step.
- `themeMetric`/`themeAvgMcap`/`themeMomentum` are **not merged** — each `valueKind` picks the right
  existing helper (mcap stays simple-average/bare-number; mom stays cap-weighted `{value,excluded}`).
- `computeCarryover` is **left as-is** for E2.1 (still ranks the same 6 / imputes ev+dfcf → keeps
  byte-identity); generalizing it is a flagged follow-up (E2.x).

### 2c. Persistence / versioning / migration (symmetric with `themes`)
- **Save** a serializable projection only: `state.portfolio.metrics = state.metrics ? state.metrics.map(m=>({key:m.key})) : null` (order-carrier). Weights/penalty still saved separately, untouched.
- **Load:** if `p.metrics` is a non-empty array → `reattach closures by key` from `DEFAULT_METRICS` via a
  `validateMetrics` helper (**dedupe by key, drop unknown keys**); else `state.metrics=null`. Never bypass
  the existing weights/penalty migration.
- **Snapshot / restore / migrateVersions:** add `metrics` (the `{key}` projection) symmetric with `themes`;
  old snapshots without it ⇒ null ⇒ defaults (byte-identical).

### 2d. Scope boundaries (deferred)
- **UI clusters stay hardcoded to the 6** (weight inputs, penalty inputs, `wEffNote`, notes/methodology,
  fundamentals table + tags + tfoot, the readWeights/onPenalty listeners) → **E2.2** (the picker UI).
- **`computeCarryover`** generalization, **`buildTxn`'s** lossy `weights:{peg,ev}` snapshot → later cards
  (changing buildTxn would alter version records = a behaviour change).
- `overridable`/`overrideKey` are **descriptive metadata only** in E2.1 (the getter closures already bake
  in the real override behaviour); wiring click-to-override generically is a later step.

## 3. Acceptance criteria
- [ ] **Byte-identity at the default 6** (`state.metrics=null`): every `r.alloc`, `r.<key>N`, `r.<key>Score`,
  `A.wPeg…wMo`, `A.cap`, and `Object.keys(A.carry)` are **exactly equal** to pre-E2.1 across scenarios:
  default seed; a book with a bank (carry-over); all-empty themes (early return); a loss-maker (null P/E);
  a zero-momentum theme; all-zero weights (the `||1` guards). **maxDiff = 0** (not epsilon — fixed order).
- [ ] Row shapes unchanged: `r.peg/ev/dfcf/pe` are `{value,penalized,excluded}`, `r.mcap` a **bare number**,
  `r.mom` `{value,excluded}` (no `penalized`) — so the fundamentals table readers are untouched.
- [ ] `state.metrics` persists (as `[{key}]`), restores via undo/redo/revert, migrates (old portfolio /
  old snapshot with no `metrics` ⇒ defaults). Weights/penalty migrations still fire.
- [ ] **Generality proof:** injecting a modified `state.metrics` (drop a metric; reorder) makes the engine
  adapt (blend over the active list) with no error; reverting restores byte-identity.
- [ ] Every downstream reader (fundamentals table, notes %s, drift, renderCalc) renders unchanged.

## 4. Implementation checklist (audit-derived, 21 steps)
See the audit synthesis; in short: (1) `DEFAULT_METRICS` + `metrics()`/`metricByKey`; (2) `state.metrics:null`;
(3–12) refactor `computeAllocation`'s per-metric stages to loops keyed by descriptor, emitting flat aliases
+ `wByKey`; (13) leave `computeCarryover`; (14–18) save/load/snapshot/restore/migrate the `{key}` projection
+ `validateMetrics`; (20) leave `buildTxn`; (21) leave the UI clusters hardcoded (verify only) — comment

## Open decisions (recommended defaults — confirm at sign-off)
1. **Serialize `[{key}]` only** (order-carrier; closures re-attached by key) — *recommended*; richer
   editable per-metric fields come with E2.2.
2. **Leave `buildTxn`'s lossy `weights:{peg,ev}`** as-is (preserves byte-identical version records);
   a full-weights snapshot is a separate cleanup.
3. **`computeCarryover` stays hardcoded** to the 6 / ev+dfcf imputation for E2.1 (needed for byte-identity);
   generalized later.
4. **Unknown/duplicate keys on load** → dedupe by key + drop keys not in `DEFAULT_METRICS`.
5. **Engine-only this step**; the weight/penalty inputs + notes + fundamentals table stay hardcoded until
   **E2.2**.
6. **`overridable`/`overrideKey`** are descriptive metadata only in E2.1; click-to-override wiring is later.
