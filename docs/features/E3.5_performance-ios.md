# E3.5 — Performance + iOS parity

- **Epic:** E3 · **Stage:** done *(integrated to `main` 2026-07-13; iOS parity gap tracked in APP1 / docs/APP_MIGRATION.md)*
- **Platform:** web + iOS · **Depends on:** E3.1

## Summary
Keep statement loading cheap and correct across platforms: a per-symbol cache with negative TTL, holdings-only
warming, lazy Screener loading, and on-device iOS parity.

## What shipped
- **Server cache (`server.py`):** `_stmt_cache = {sym:{ts,data}}` — per-symbol, `STMT_TTL=24h` for names with data,
  `STMT_NEG_TTL=6h` for the empty sentinel (so a late filing is picked up within hours). `get_statements` is lazy:
  only fetches missing/stale symbols (Screener names load strictly on demand) and returns every cached symbol.
- **Warm daemon (`server.py` `main`):** a low-priority daemon warms **holdings only** (not all 25) **after** the
  quotes/fundamentals warm, so first paint is unaffected; logs a coverage line (holdings without statements).
- **Client (`www/index.html`):** `force` threaded through `webStatements`/`dsStatements`/`loadStatements(syms,force)`;
  the **Refresh fundamentals** button now also force-reloads statements. `openStockDetail` lazy-loads a single
  symbol's statements on demand.
- **iOS parity:** `nativeStatements` fetches `fundamentals-timeseries` on-device (same crumb dance, same
  `STMT_FIELD_MAP`, same normalized shape, skips nulls, keeps ≤9 quarters) so the compute engine behaves identically
  on web and native.

## Notes / measured
- The endpoint is light (~60 ms/name); Yahoo caps quarterly history at ~5 quarters (confirmed). A full 27-name
  statement load is a few hundred ms in parallel.

## Acceptance criteria
- [x] Screener names load statements only when opened; holdings warm in the background.
- [x] A second load within TTL hits the cache; the empty sentinel throttles sparse names to the 6h window.
- [x] `nativeStatements` returns the same shape as `/api/statements`.
