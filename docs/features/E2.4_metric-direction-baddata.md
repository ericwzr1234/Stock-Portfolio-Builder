# E2.4 — Per-metric direction & bad-data handling

- **Epic:** E2 · User-Defined Metrics
- **Stage:** done  *(integrated to `main` 2026-07-01)*
- **Platform:** web + iOS · **Depends on:** E2.2, E2.3

## 1. Summary
Generalizes C2 (bad-data handling) to **any** metric. Group ② is **one row per active metric**: an auto-assigned
scoring **direction** (read-only — pulled from the catalog map, never asked), a bad-data **policy** — the same
three offered for **every** metric including the original 6: **Penalize** (artificial value) / **Carry over**
(impute from quality) / **Ignore** (exclude the name) — and, for lower-better metrics under *penalize*, the
**artificial value**. Per-metric overrides live in `state.metricCfg` (pruned-on-default; `null` ⇒ baked-in
descriptor defaults), so the default 6 stay byte/behaviour-identical.

## 2. What shipped
- **`state.metricCfg`** `{key:{penalty?,badData?}}` + resolvers `cfgOf/effBadData/effDirection/effPenalty`.
  `effDirection(m) = m.direction` (**auto from the map — never editable**). **Prune-on-default:** any edit that
  returns a metric to its descriptor default deletes the field; an empty entry is deleted; `{}` collapses to
  `null` (a round-trip serializes `null`, not `{}`).
- **`#metricCfgRows`** (delegated listeners): label + **read-only direction badge** (all metrics) + a policy
  `<select>` offering **Penalize / Carry over / Ignore for every metric** + an artificial-value `<input>` shown
  only for **lower-better** metrics under *penalize* (higher-better bad values are treated as worst = 0, so no
  number is needed). Focus-guarded rebuild.
- **Uniform engine wiring:** `computeAllocation` computes `pol = effBadData(m)` and a direction-aware
  substitute (`higher ⇒ 0`, `lower ⇒ effPenalty(m)`; *ignore* ⇒ exclude) and passes it to **all three metric
  kinds** — `themeMetric`, and now the **policy-aware `themeAvgMcap`/`themeMomentum`** (so mcap & momentum honor
  the policies too). `getFor()` gates carry on `effBadData==='carry'` using `m.key`.
- **Generalized carry-over:** `computeCarryover` imputes **any** carry-policy metric at the name's composite-
  quality percentile (goodness space by direction), while reproducing the exact ev/dfcf imputation for the
  default 6 (byte-identical). Penalty writes route by `penaltyKey` → `state.penalty` (the 6) else
  `state.metricCfg[key].penalty`; catalog metrics get a direction-appropriate default (higher ⇒ 0, lower ⇒ 1000).
- **Persistence:** `metricCfg` round-trips through save/load/snapshot/restore/migrate (symmetric with `metrics`).

## 3. Acceptance criteria
- [x] Direction is auto (read-only badge) for every metric; the user is never asked higher/lower.
- [x] All three policies (penalize / carry / ignore) are offered for **every** metric, incl. mcap & momentum.
- [x] Default 6: rows show correct direction/policy/penalty (PEG ↓/penalize/10; EV ↓/carry; mcap ↑/exclude);
  engine output + `.penalized`/`.excluded` lists byte-identical (verified via git before/after: maxDiff=0).
- [x] Set a catalog metric (e.g. ROE) to **carry** → a name missing that metric is imputed (MSCI), not dropped.
- [x] Change a penalty → the `prem` tag text + blend update + persists; edit-then-revert → `metricCfg` ⇒ `null`.
- [x] Change EV carry→ignore → bank names drop from the EV average.
