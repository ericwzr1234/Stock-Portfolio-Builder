# E1.1 — Data-driven theme list (foundation)

- **Epic:** E1 · User-Defined Themes
- **Stage:** design  *(awaiting sign-off)*
- **Platform:** web (then migrate to iOS)
- **Depends on:** —

## 1. Summary
Today the **set** of themes (their keys, names, colours) is a hardcoded `THEMES` const — only the
*membership* (which tickers are in each) is dynamic (`state.themeTickers`). This feature makes the
**theme list itself data-driven** (`state.themes`), so the whole app — the allocation engine, every
tab, the cap, the version timeline — works with *any* number and set of themes. It is **invisible
and regression-safe**: with the default 5 themes the app behaves exactly as it does now. This is the
plumbing that the later cards (create/rename/delete themes, custom screener, recommendations) build on.

## 2. Design
**Data model**
- Keep `THEMES` (the current 5 `{key,name,color,tickers}`) as the **defaults**.
- Add **`state.themes`** = array of `{key, name, color}` (membership stays in `state.themeTickers`).
  `null` ⇒ use the defaults. Persisted in `portfolio.json` and in **every version snapshot**.
- Add accessors: **`themes()`** → `state.themes` if set, else the default `{key,name,color}` list;
  **`themeByKey(key)`**. From now on the live theme list is read only through `themes()`.

**Behaviour / refactor (no functional change at N=5)**
- Replace every direct iteration of the `THEMES` const for the *live* list with `themes()`:
  `computeAllocation`, `planTrades`, `rebuildThemeOf`, and the renderers
  (`renderPrices`/`renderFundamentals`/`renderScreener`/`renderCalc`, the allocation bar, legend, and
  drift table). Membership inside a theme is read via `tickersOf(t.key)` (already dynamic).
- **N-adaptive defaults** (so the model scales when the theme count changes later):
  - equal-weight base = `1/N` (N = `themes().length`) — already what `applyThemeCap` uses (`rows.length`).
  - **per-theme cap default = `1.5 / N`** → `0.30` at N = 5 (identical to today). A user-set `state.cap`
    is preserved; only the *default* (unset) value scales with N.

**Persistence / versioning / migration**
- `snapshotState()` also captures `themes`. `restoreVersion()` restores `state.themes` (+ `rebuildThemeOf()`).
- `savePortfolio()` writes `state.themes`; `loadPortfolio()` reads `p.themes` (absent ⇒ `null` ⇒ defaults).
- Old `portfolio.json` and old version snapshots with no `themes` ⇒ default 5. **No migration UI needed.**

**Edge cases**
- A theme key not present in `www/data/universe.json` (a future custom theme): `renderScreener`
  handles it gracefully (empty curated list; held names still show). E1.1 just makes this *not crash*;
  building custom-theme screening is **E1.4/E1.7**, out of scope here.
- Colours come from the defaults for now; the custom-theme colour picker is **E1.4**.

## 3. Acceptance criteria
- [ ] **Regression:** with `state.themes = null`, the app is behaviourally identical — same 5 themes
  everywhere, same allocations, same Prices/Fundamentals/Screener/Calculator/History behaviour, same
  rebalance math and version timeline.
- [ ] `state.themes` **persists** to `portfolio.json` and is **restored** by undo / redo / revert
  (it's in the version snapshot).
- [ ] An **old** `portfolio.json` (no `themes` field) loads cleanly → defaults to the 5.
- [ ] **Generality proof:** injecting a modified `state.themes` (e.g. 3 themes; 7 themes; a renamed /
  recoloured theme) makes **all tabs + the engine + the rebalancer adapt** — N-derived cap & equal-weight,
  every loop, the `sym→theme` map — with no errors. (Verified by setting `state.themes` in the
  console, exercising allocation + a realign, then reverting.)
- [ ] The `THEMES` const is no longer iterated directly for the *live* list anywhere (only as the
  default source inside `themes()`).

## 6. iOS migration notes
- Pure `www/index.html` change → Mac runs `npx cap sync ios`. **No native/Swift change.** The
  `.native` skin reuses the same renderers, so it adapts automatically. The new persisted `themes`
  field flows through the same portfolio save/load (localStorage + LAN sync) with no extra work.
