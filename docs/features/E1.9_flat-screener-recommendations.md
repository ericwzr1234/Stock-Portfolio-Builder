# E1.9 — Flat Screener: pooled recommendations + per-stock actions

- **Epic:** E1 · User-Defined Themes
- **Stage:** testing  *(implemented on `dev`; verified live 2026-06-26)*
- **Platform:** web (then iOS) — **adds a server route + iOS data-layer call** (`/api/peers` / `dsPeers`)
- **Depends on:** E1.1–E1.4 (themes), E1.3 (search). **Delivers the recommendation ideas from E1.7
  (peers of a theme's picks) and E1.8 (keywords from a theme's name).**

## 1. Summary
Replace the Screener's five per-theme tables with **one running list**: ~15 recommendations per theme
(not grouped or ordered by theme) **plus all current holdings**, sorted by market cap. Every row is
actionable — **tap to add to a theme, swap into a theme, watchlist, or (for a held name) remove it**.
For the original themes recommendations come from the curated universe; for **custom themes** they're
generated live from the **theme name (keywords) + sector peers of the theme's current picks**.

## 2. Design
### 2a. The list
- For each theme, gather **up to 15 candidates**: curated top-15 by live market cap (original themes), or
  the cached **keyword + peer** recos (custom themes). Tag each candidate with its theme.
- **Always include every holding** (tagged `held`, theme = its current theme).
- Flatten + dedupe + **sort by market cap**; render one table: Stock · Theme chip · Mkt cap · Price · Day
  · Action. No theme grouping.

### 2b. Recommendations for custom themes (`buildThemeRecos`)
- **Keywords:** `dsSearch` the theme name, its words, and de-pluralized forms (Yahoo search is
  word-picky — "Semiconductors"→1 result, "Semiconductor"→12, so we query both).
- **Peers:** for each current pick, `dsPeers` (Yahoo *recommendationsbysymbol*) → sector neighbours
  (e.g. TSM → AVGO, MU, ASML, AMD). So recs improve as a theme is seeded.
- Exclude current members + holdings; take the first 15; fetch their quotes for display.
- Cached in `state.themeRecos[key] = {syms, sig}` (sig = members + name) — recomputed only when the theme
  changes; runtime-only (not persisted). Loaded async on entering the Screener (`ensureScreener`).

### 2c. Per-stock action sheet (`openStockActions`)
Tapping any row opens a sheet with a theme picker (pre-selected to the row's theme) and:
- **➕ Add to theme** (`addTicker` → rebalance preview), **⇄ Swap in…** (`openSwap`), **☆ Watchlist**
  (`addToWatchlist`), and — if the name is **held** — **✕ Remove from «theme»** (`removeTicker`): drop a
  holding from its theme with no replacement.

### 2d. Server / data layer
- `server.py`: **`/api/peers?symbol=`** → Yahoo `recommendationsbysymbol` (no crumb needed).
- `www`: **`dsPeers(sym)`** (web → `/api/peers`; iOS → Yahoo via CapacitorHttp). `dsSearch` (E1.3) reused
  for keywords.

## 3. Acceptance criteria
- [ ] Screener is **one flat list** (no per-theme tables): ~15 recs/theme + all holdings, mcap-sorted.
- [ ] **Custom theme** (e.g. Semiconductors) shows ~15 live recs (keyword + peers); seeding it with a pick
  adds that pick's peers (verified: TSM → AVGO).
- [ ] **Held names appear** tagged `held`; tapping one offers **Remove from its theme** (drop, no swap).
- [ ] A candidate tap → **add / swap / watchlist** into the chosen theme; add/swap preview a rebalance.
- [ ] Original themes still use the curated universe (top-15).

## 4. Implementation notes
- `server.py`: `peers_yahoo` + `/api/peers`. `www/index.html`: `dsPeers`; `isCuratedTheme`,
  `buildThemeRecos`, `loadThemeRecos`, `state.themeRecos`; rewritten `renderScreener` (flat);
  `openStockActions`; `ensureScreener` calls `loadThemeRecos`; `.th-chip` style. No data-file change.

- ✅ Custom-theme recs: empty Semiconductors → 12 keyword names (NXPI/ON/TSM/LSCC/…); seeded with TSM →
  peers add AVGO etc.
- ✅ Action sheet: add / swap / watchlist for any name; **remove** shown for held names; theme pre-selected.
- ✅ `/api/peers` (NVDA → TSLA/AMZN/AMD/AAPL/META) and the keyword path both work.
